## 2.2.0 (22 Nov 2026) - PR #7, NOT deployed, NOT merged
Stay signed in (owner's P1 checklist point 35): a person signed in to the console on this phone or laptop is not asked to sign in a second time on Home. One writer, branch `claude/youthful-mayer-cop4co`, cut from `d496fc3` (the merge of PR #6 = version 2.1.0, the tip of `home-bar-qa`; its tree is identical to PR #6's head `f0d6d44`). Contract (BOSS design, with the console 0.4.0 writer): Home calls `GET https://console.corporatetambola.com/api/me` with `fetch(..., {credentials:'include'})`; the console allows credentialed CORS only for `https://home.corporatetambola.com` and answers `{"signedIn":true,...}` or `{"signedIn":false}`.
- Added: on load, gate.js asks the console that one question (plain GET, no custom headers so no preflight, 4 second limit, answer never cached). Only `signedIn === true` counts. If true, every Sign in / Sign in or start link says "Open console" (spoken name "Signed in. Open console"), links carry `visit=repeat`, and the front page shows "Signed in" on a reserved line (no layout shift). The free-game link keeps its words. Where: gate.js, index.html (`#signed-note`), site.css.
- Added: failure is silent. A network error, a 4xx/5xx, a blocked CORS answer (browser refuses it, even if the body says signedIn:true), a timeout, a body that is not JSON, `signedIn:"true"` (a string) or a missing field all leave the page exactly as before; the page raises no error of its own. Asked again when a page comes back from the back button (pageshow, persisted).
- Not done on purpose (owner's rules): the signed-in state is never written to localStorage, sessionStorage or a cookie (it is one variable that lives while the page is open); the cookie is never read (the browser sends it, the code cannot see it); no other field of the answer (e-mail, name, id) is read, shown, stored or sent anywhere; no console.log, no beacon, no second request.
- Changed: `_headers` Content-Security-Policy `connect-src 'self'` is now `connect-src 'self' https://console.corporatetambola.com`. Without this the browser would refuse the question. No other host is added; no wildcard. (Needs the Cloudflare Pages deploy of `_headers`; nothing is deployed here.)
- Changed: privacy page: one honest line on staying signed in and its limits (clearing cookies, incognito windows, the installed phone app keeps its own sign-in, Safari may close it sooner; the word "private" is not allowed on this site by T09, so "incognito"), and the sentence "Its own code sends nothing anywhere" now says that one plain question goes to the console and is never saved. Update date 22 Nov 2026. Where: privacy.html.
- Changed: the top-bar Sign in button keeps one width in both states, so nothing in the bar moves: 10rem from 1280 px ("Open console"); from 900 to 1279 px only "Console" shows (no room for more; spoken name stays "Signed in. Open console"), with tighter padding below 1160 px. Script/style marks: gate.js v2, site.css v8. Sitemap dates 2026-11-22. Version 2.2.0 in version.json, package.json, package-lock.json, README, footer (built) and /changes (built).
- Tests: new T24 (96 checks): the code and policy read as text; signed out; signed in (request is one GET with the console cookie, Origin = the page, no preflight; the e-mail, name and id in the answer appear nowhere); reload forgets; back button asks again; other pages; "Yes, remember me" does not fight it; no layout shift on five pages from 320 to 1440 px (every box measured before and after, and the browser's layout-shift score); 500, 404, not-JSON, string "true", missing field, network failure; four blocked-CORS shapes; a console that never answers (page loads at once, gives up at 4 seconds); axe rules. Every page-opening test now has a stub console, T13 allows exactly that one outside request and checks the policy. T24 has break-it-and-see-red runs in tests/falsify.mjs.
- CI: the break-it job's limit is now 60 minutes (it passed in 30 before T24 and was cancelled at 30 with it), and every test case now has a 240 second limit (`CASE_LIMIT_MS`): on one CI run a single browser call hung for 39 minutes after the 12th T24 break-it; a stuck case now counts as failed (red) instead of stalling the job.
- Known limits: (1) Home cannot tell why it is signed out (cleared cookies, incognito window, the installed phone app has separate storage, Safari ITP) and says so only in the privacy line. (2) This works only if the console's cookie is sent on a call from home. to console., which holds when both sit under the same site (corporatetambola.com) and the cookie is not blocked; a browser that blocks it shows the normal Sign in button. (3) Not testable here: the real console (the console 0.4.0 writer builds `/api/me`; the proxy in this build box also blocked both hosts), so the tests use a stand-in that answers the contract. (4) A truly absent CORS header cannot be produced through the test tool (it adds one), so that shape is tested as `Access-Control-Allow-Origin: null`; the browser refuses both the same way.
- Audits: two independent audits requested on the exact commit; PASS ids: pending. Rollback id (previous deploy): deployment `80117044` (per BOSS; the live 2.1.0 deployment is `99eb639f`).

## 2.1.0 (21 Nov 2026) - PR #6, merged into home-bar-qa as d496fc3; live (deployment 99eb639f, rollback 80117044, as told by BOSS; not read from the site by this writer)
Honest cookie and offline behaviour, a privacy signal, fairness wording only where true. One writer, one branch (`claude/modest-bohr-7dphxw`), off `home-bar-qa` at 772db2f (2.0.0). The older open PRs (#2 SEO pass, #5 smoke test) are on other lines and are NOT part of this change.
- Fixed: a "No" did not stop an older offline helper (service worker) from saving files again while the page was still open. Found by test: after No, a page that asked for more files brought the saved copy (`home-v11`) back, and it stayed until the next page was opened. Now the page tells the helper to stop and delete, removes the helper, deletes every `home-` copy, and, while an older helper that cannot be told still runs the page, deletes again every 0.3 seconds. Where: site.js, sw.js.
- Fixed: the offline helper started saving files the moment it was installed. Now install saves nothing; the page asks for the copy (`ctz-keep`) only after a Yes, and the helper adds files only to a copy that already exists, so it can never make a new one after a No. Cache name is now `home-v12`; older `home-` copies are deleted when the new helper takes over. Where: sw.js, site.js.
- Added: privacy signals. Global Privacy Control (and the older Do Not Track) counts as No: the question is not shown, nothing is stored (not even an answer), an old Yes given before the signal is forgotten (visit note removed, offline copy removed). The footer "Cookie choices" still opens the question, which then says the signal counts as No until you press Yes; a Yes pressed with the signal on is your own word and wins (stored with `s:1`).
